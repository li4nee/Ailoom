# Milestone 5 — Widget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `<script>` tag on any allowed site shows an accessible chat widget that streams cited answers, offers and performs handoff, takes feedback, receives agent replies live, and resists hostile host pages, other origins, and scripted abuse.

**Architecture:** spec §10.4, §16, §17.9, §18; architecture §5.2. Widget API under `/api/widget/v1` authenticated by a visitor JWT; answers reuse `ChatOrchestrator` + `SseAnswerSink`; widget is MIT, Preact, Shadow DOM, loader ≤ 3 KB, main ≤ 25 KB gzipped.

**Tech Stack:** jose, altcha-lib, Preact, Vite library mode, size-limit, Vitest + happy-dom, Playwright.

**Spec:** `docs/spec.md`, `docs/architecture.md`. Index: `2026-11-09-00-index.md`.

## Global Constraints

All index constraints apply. Milestone-specific:

- Visitor token: JWT HS256 with `WIDGET_SECRET`, claims `{ sub: contactId, bot: botId, ws: workspaceId, aud: 'widget' }`, TTL 30 days, sent as `Authorization: Bearer`; stored in `localStorage` under `<project>:<publicKey>:token` (all storage access in try/catch with in-memory fallback).
- Every widget request re-checks `Origin` against the bot's `allowed_origins`; CORS never allows credentials.
- Both widget streams (message POST and live-events GET) use `fetch` + `readSse` because they need the `Authorization` header (EventSource cannot send it). Update spec §16.3 and architecture §5.2 accordingly in Task 5.9.
- Rate limits (spec §20.4): session create 30 / hour / IP; visitor messages 20 / min and 200 / day per contact; 600 / min per bot.
- Custom element name: `<project>-chat` (placeholder `ailoom-chat`); global API `window.<Project>Chat` (placeholder `window.AiloomChat`).
- The widget package imports only from `@app/shared` (lint rule `no-agpl-import`).

## Review Focus (this milestone)

1. **Visitor's `localStorage` blocked** (Safari private mode, third-party storage partitioning, sandboxed iframes). Expected: widget works for the page lifetime with an in-memory token, no console errors. → Task 5.9 test.
2. **Host page with aggressive CSS and a strict CSP** (`* { all: unset !important }`, `script-src` allowing only the platform origin). Expected: widget renders correctly inside Shadow DOM; no inline scripts or `eval` needed. → Task 5.16.
3. **Mobile keyboard and small screens** (< 480 px, virtual keyboard open). Expected: full-screen panel, composer stays visible (`100dvh`), focus not lost on rotate. → Tasks 5.12, 5.16.
4. **Network drop mid-answer.** Expected: the widget shows the partial answer marked "interrupted", offers retry, and the live channel reconnects with `Last-Event-ID` without duplicating messages. → Tasks 5.7, 5.10.
5. **Bot key rotated or origin removed while a visitor has the widget open.** Expected: next request gets `403 origin_not_allowed` or `401` → widget shows "Chat is unavailable right now" instead of a broken state; a rotated key with a still-valid visitor token keeps working (token is bound to the bot id). → Tasks 5.2, 5.10.
