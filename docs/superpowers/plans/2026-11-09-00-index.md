# Phase 0 + Phase 1 Implementation Plan — Index

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the self-hosted AI customer support platform from an empty folder to the `v0.1.0` release defined in spec §26.

**Architecture:** pnpm + Turborepo monorepo. NestJS (Fastify) `api` + `worker` from one image, React SPA admin served by Caddy, Preact widget, Postgres 18 + pgvector ≥ 0.8 + pg-boss as the only stateful service, Vercel AI SDK behind one `Llm` service. Details: `docs/architecture.md`.

**Tech Stack:** Node 24, TypeScript strict, NestJS 11, TypeORM 0.3.x, pg-boss, Zod 4, nestjs-zod, nestjs-cls, jose, @node-rs/argon2, Vercel AI SDK (`ai`, `@ai-sdk/*`), @huggingface/transformers, React 19, Vite, TanStack Router/Query, Tailwind + shadcn/ui, Preact, Vitest, Testcontainers, Playwright, Caddy 2, Astro Starlight.

**Spec:** `docs/spec.md` (what) and `docs/architecture.md` (how). Executors read both before starting any milestone.

## Global Constraints

Every task in every milestone includes these requirements.

- Runtime: Node **24** LTS (`.nvmrc` = `24`, `engines.node` = `>=24 <25`), pnpm **10** via `packageManager`.
- Database: PostgreSQL **18** with pgvector **≥ 0.8**, image `pgvector/pgvector:pg18`. Primary keys `default uuidv7()`.
- TypeScript: the `packages/tsconfig/base.json` flags in architecture §7.1, no `any`, no non-null assertions outside tests, `assertNever` on every union `switch`.
- ORM: TypeORM 0.3.x, `synchronize: false` everywhere; raw SQL only inside `*.repository.ts` with a comment explaining why.
- Tenant tables: accessed only through `TenantRepository<T>` subclasses whose methods take `workspaceId` first.
- Config: only `apps/api/src/common/config/` reads `process.env`.
- LLM: only files under `apps/api/src/providers/` import `ai` / `@ai-sdk/*`; everything else calls the `Llm` service (dependency-cruiser rule, Task 0.18).
- Outbound HTTP to user-supplied or provider URLs: only through `safeFetch`.
- Licensing: AGPL-3.0-only for `apps/api`, `apps/admin`; MIT for `packages/*`; CC-BY-4.0 for `apps/docs/src/content`. First line of every source file: `// SPDX-License-Identifier: <id>` (or `/* … */` for CSS, `<!-- … -->` for HTML/MD files that carry headers). MIT packages never import from `apps/*`.
- API: JSON camelCase; error envelope `{ error: { code, message, details?, requestId } }`; cursor pagination `{ data, nextCursor }`; every response carries `X-Request-Id`.
- Time: all day/month buckets in UTC; business code uses the injected `Clock`.
- Tests: integration tests use real Postgres via Testcontainers; no real network in tests (the harness blocks it); the `mock` provider everywhere except the manual live workflow.
- Never mention any company other than the copyright holder in files, headers, or metadata.
- Dependencies: pin exact versions in the lockfile; each new runtime dependency is justified in the PR description (what, why, license, size).

## Review Focus (whole project)

The five failure modes most likely to bite real users that the spec implies but does not spell out. Each has a pinning test in the named task.

1. **A visitor sends a message while a previous answer is still streaming** (double click, two tabs). Expected: the second request gets `409 answer_in_progress`; no interleaved deltas, no duplicate AI message. → Task 4.8.
2. **A crawled site returns a 200 "soft 404" or a login page for many URLs.** Expected: pages under 50 words get `low_text_content`, are kept out of the index, and the source still reaches `ready` with a warning count, not `failed`. → Task 3.7.
3. **An operator changes a bot's embedding model twice before the first re-embed finishes.** Expected: the first re-embed job is cancelled, its partial rows deleted, only the latest model is applied. → Task 3.10.
4. **Clock/timezone edges for spend caps:** a message at 23:59:59 UTC on the last day of a month and one at 00:00:00 UTC the next day go to different months; the cap resets exactly at the UTC month boundary. → Task 4.6.
5. **A workspace is deleted while ingestion and chat are mid-flight.** Expected: running jobs stop at their next existence check without errors, the open widget stream ends with `error: bot_unavailable`, and the purge job leaves zero rows with that `workspace_id`. → Tasks 1.12 and 4.8.
